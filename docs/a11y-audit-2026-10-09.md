# Accessibility audit — 2026-10-09 (branch `sara/a11y-pass`)

Base: `origin/main` @ `0317daf`. Scope: keyboard navigation, focus visibility,
names on icon-only controls, form labels, WCAG 2.1 AA colour contrast.

## Method

- **Automated:** axe-core 4.12 (tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`)
  injected via Playwright into `next dev` running with placeholder Supabase
  env and the built-in demo cookies (`mh_demo_user`, `mh_guest_profile`).
  44 routes, light **and** dark colour schemes; auth pages (`/login`,
  `/register`, `/forgot-password`, `/reset-password`) re-run signed out and
  `/onboarding` with a not-yet-onboarded demo user. Pages therefore render their
  signed-out / empty-data states; listing cards, swipe cards and map pins with
  real rows were not exercised (no secrets on the box).
- **Keyboard (Playwright):** 30 Tab presses on `/discover`, `/deal-check`,
  `/fleet`, `/settings` — every stop shows a visible ring, no traps. Dialogs
  checked for initial focus, Tab containment, Escape-to-close and focus return:
  Decision guide drawer, state picker, command palette (⌘/Ctrl-K), account
  menu, location menu.
- **Static:** TypeScript-AST scan for `<button>`/`<a>`/`<Link>` whose only
  children are icons and that carry no `aria-label`/`title`; grep for
  `fixed inset-0` overlays without `role="dialog"` / Escape handling; grep for
  `focus:outline-none` without a replacement ring.

## Left as-is (with reason)

- **`/showcase` `nested-interactive` (5):** the demo DNA carousel uses
  `role="button"` slides that contain links. Marketing demo component
  (`components/ui/dna-carousel.tsx`); restructuring it is a design change, not
  an a11y patch. Low traffic.
- **Unused demo kits** `components/ui/live-data-carousel.tsx`,
  `production-ready.tsx`, `carousel-showcase.tsx` contain unnamed icon buttons
  but are imported nowhere; not touched.
- **Data-dependent UI** (deal cards with rows, swipe deck, map pins, gallery
  thumbnails) could not be rendered without Supabase secrets; covered only by
  static review. Worth repeating axe in May's signed-in pass.
- `focus:outline-none` on text inputs that swap to `focus:border-*` was left
  (border change is the visible indicator); `DealCard`, `DiscoveryCard` and
  `Field` already replace the outline with a `focus-visible:ring-2`.

## Notes for May (her files — not edited here)

- **`components/saved/FindSimilarModal.tsx` (PR #191):** close button (≈L103)
  and the icon-only "open deal" `<Link>` (≈L199) have no `aria-label`; the
  modal has no `role="dialog"`, Escape or focus trap. Drop-in:
  `useDialogA11y(open, onClose, panelRef)` from `hooks/useDialogA11y.ts` +
  `role="dialog" aria-modal="true" aria-labelledby=…`.
- **`components/BottomNav.tsx` (Saved badge, `background: var(--accent)`) and
  `components/layout/TopNav.tsx` (alert badge, `background: var(--amber)`):**
  `text-white` is 2.0:1 in dark theme → use `text-[var(--on-accent)]`.
- **`app/onboarding/page.tsx` (PR #187):** ≈L667 `bg-[var(--accent)] text-white`
  CTA is 2.0:1 in dark → `text-[var(--on-accent)]`; the step dots
  `<div aria-label="Setup step 1 of 4">` trip axe `aria-prohibited-attr` → add
  `role="img"` (or `role="progressbar"` with `aria-valuenow/max`).
- AccountMenu + location menu: Escape closes and `aria-expanded` toggles
  correctly — no action needed.
